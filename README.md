# Moai Idle Game — 모아이 키우기

팀 프로젝트 '이순신 키우기'를 개인 프로젝트로 **전면 리빌딩**한 Merge 방치형 모바일 게임입니다.  
기존 구조의 문제를 분석하고, 데이터 설계·오브젝트 관리·콘텐츠 구조를 처음부터 다시 설계했습니다.

## 전작 대비 개선 내용

| 항목 | 이순신 키우기 (전작) | 모아이 키우기 (본작) |
|------|------|------|

## 기술적 고민

### 1. Object Pool 적용으로 모바일 성능 안정화

캐릭터, 골드 텍스트, 보상 이펙트처럼 반복 생성되는 오브젝트가 많아지면서 간헐적 프레임 드랍이 발생했습니다.

- Instantiate / Destroy를 반복하는 구조에서 **Object Pool**로 전환해 GC 할당 빈도를 줄임
- 풀 사이즈 부족 시 자동 확장되도록 구성해 부족 상황에서도 오류 없이 동작하게 처리
- 모바일 환경에서 프레임이 안정적으로 유지됨을 기기 테스트로 확인

### 2. PlayerPrefs 한계 → JSON 기반 저장 구조 전환

전작에서 PlayerPrefs와 JSON이 혼용되어 데이터가 어디 저장됐는지 추적이 어려웠습니다.

- **SaveData 클래스**를 정의해 모든 게임 데이터를 하나의 구조체로 묶어 JSON 직렬화
- 캐릭터 상태, 재화, 업적 진행도, 오프라인 보상 계산 기준 시각까지 단일 파일로 관리
- 기능 추가 시 SaveData 필드 하나만 추가하면 되도록 확장 구조 확보

## 회고

**어려웠던 점**
- 전작 코드를 처음부터 다시 쓰면서 "기능 추가"보다 "기존 구조의 문제를 먼저 정의하는 것"이 더 어려웠습니다.
- PlayerPrefs 기반 저장 구조는 데이터가 늘어날수록 어떤 키로 뭘 저장했는지 추적이 힘들었고, 초반에 구조를 전면 변경하는 결정을 내리는 것이 쉽지 않았습니다.

**배운 점**
- 리빌딩을 통해 "처음부터 데이터 구조를 어떻게 잡느냐"가 이후 기능 추가 속도에 직접 영향을 준다는 것을 경험했습니다.
- Object Pooling은 적용 범위가 넓을수록 효과가 커지지만, 풀 사이즈 설계를 잘못하면 예외 상황이 생긴다는 것을 알게 됐습니다.
